# Аудит standalone NRO и удаление WebKit — 16 ноября 2026

## Вывод

На ветке `main` standalone NRO запускал не production native интерфейс, а отдельный
WebKit host. Это подтверждено исходным кодом `src-switch/main.cpp`: после
`romfsInit()` он вызывал `webOfflineCreate(... WebDocumentKind_OfflineHtmlPage ...)`
и затем `webConfigShow()`. Пути `app.htdocs/index.html` и `.htdocs/index.html`
искались внутри встроенного RomFS.

В то же время полноценный native интерфейс уже существовал в `source/main.cpp` и
собирался в HOME library applet через `projects/DeskNXMenu/Makefile`. В нём есть
SDL2 window/renderer, контроллерный и сенсорный ввод, каталог, рабочие столы,
сохранение, диагностика и отдельные compile-time ветви для standalone и system applet.

Следовательно, проблема была архитектурной: обычный NRO и HOME applet использовали
разные точки входа и фактически разные UI. Код offline Web Applet оставлял запуск
standalone NRO зависимым от HTML/RomFS/WebKit и мог приводить к ошибке группы 2808.
Точный смысл суффикса `1037` этим аудитом не установлен; не следует трактовать его
как доказательство конкретной ошибки HTML-файла.

## Изменения Phase 0

1. Standalone `Makefile.switch` переключён на production `source/main.cpp` и
   supporting modules из `source/` и `projects/DeskNXMenu/source/`.
2. Prototype `projects/DeskNXMenu/source/main.cpp` исключён из standalone target,
   как и из HOME applet target, чтобы не возникало двух `main()`.
3. Standalone target собирается без `DESKNX_SYSTEM_APPLET`; системные IPC и heartbeat
   остаются специфичными для HOME applet target.
4. Из standalone build pipeline удалены npm/Vite, React, TypeScript, HTML, подготовка
   RomFS и вызовы offline Web Applet API.
5. Обновлён NRO checker: он требует NRO0/ASET/NACP и отвергает непустую RomFS section.
6. Добавлена статическая проверка standalone entrypoint; repo-hygiene теперь запрещает
   возвращение удалённой web-инфраструктуры в tracked build/runtime paths.
7. README, feature inventory, frontend plan и diagnostics приведены в соответствие
   с native архитектурой.

## Проверки и границы

- CI native cross-build и host tests: ожидается после push этой ветки; до результата
  их статус — NOT RUN.
- Проверка структуры NRO: включена в CI, ожидается после сборки.
- Физическая Nintendo Switch: NOT RUN. Этот commit не доказывает устранение
  `2808-1037` на консоли до установки и запуска нового артефакта.
- HOME takeover, lifecycle, sleep/wake и восстановление остаются отдельными
  аппаратными проверками. Не устанавливать экспериментальный qlaunch backend
  как повседневную замену HOME.

## Риски, которые остаются

- Standalone native UI теперь ссылается на те же библиотеки/модули SDL, что и HOME applet;
  необходимо подтвердить фактическую компиляцию в Actions.
- Системные сервисы NS/account/PDM и запуск игр имеют ограничения по контексту приложения.
- Chain-load NRO доступен только при успешном `envHasNextLoad()`; иначе UI сообщает
  об ограничении и предлагает использовать поддерживаемый hbmenu/title-override workflow.
