## Исправления, внесённые во время аудита

### 1. Высокий приоритет — проверка границ NRO в hbloader

Ранее код вычитал размер заголовков из `header->size` до проверки минимального размера, читал NRO-данные в фиксированный heap до полной проверки размеров и проверял диапазоны сегментов после чтения. Повреждённый или специально сформированный NRO мог вызвать underflow размера чтения или выход за границы буфера.

Теперь до чтения остатка образа проверяются:
- успешный `fstat` и размер файла;
- минимальный размер NRO;
- соответствие размера образа размеру файла и heap;
- допустимый размер BSS;
- диапазоны всех трёх сегментов с расширенными целочисленными вычислениями.

В target-mode некорректный NRO логируется, после чего loader завершает applet-сессию, чтобы backend мог вернуть меню, вместо показа фатального loader error. Полный system run #128 на `72b8bff` успешно собрал hbloader и qlaunch backend после этих изменений.

### 2. Средний приоритет — ограничение кэша каталога с SD-карты

Кэш раньше читался через неограниченный `getline`; повреждённая строка могла привести к большой аллокации на ограниченной памяти Switch. В строгом парсере числа использовался ошибочный многосимвольный литерал `'\\0'` вместо `'\0'`, из-за чего валидные числовые поля кэша отвергались и кэш мог пересоздаваться при каждом запуске.

Добавлены ограничения размера файла и строк, лимиты полей и числа записей, строгий тестируемый разбор целых без пробелов/суффиксов и переполнений, проверка типа записи, размеров плиток/цвета, 16-символьного hex Title ID и существующего NRO по пути `sdmc:/switch/`. Парсер чисел выделен в host-testable `include/desknx/StrictParse.hpp` и покрыт граничными тестами. Кэш с некорректными данными отклоняется и пересоздаётся.

### 3. Средний приоритет — ограничение истории запусков

История с SD-карты теперь проверяется на тип файла и общий размер до чтения; длина строк и полей ограничена. Некорректные записи пропускаются.

### 4. Средний приоритет — очередь CI

В оба workflow добавлена отмена устаревших запусков на той же ветке/ref. Это предотвращает накопление одновременных сборок системных зависимостей после последовательных коммитов.

### 5. IPC

Общие правила IPC проверяют размер payload без предварительного сужения к 32-битному типу. Для Busy выделен отдельный сигнал завершения; тесты покрывают границы размера и длительности. UI отправляет Busy вокруг системной клавиатуры и пытается закрыть паузу после возврата.

### 6. Исправление production storage reads и payload contract

В HOME library applet использовалась несуществующая для актуального libnx пятиаргументная форма `appletStorageRead`; размер перед чтением теперь проверяется через `appletStorageGetSize`, затем вызывается актуальная четырёхаргументная функция. Удалён вызов несуществующего `accountGetZeroUid`; при отсутствии выбранного пользователя используется нулевой `AccountUid`. Контракт `LaunchTitle` исправлен: v2 payload имеет 32 байта, legacy v1 — 8.

### 7. Защита геометрии и идентификаторов

Проверка координат сетки теперь исключает переполнение `x + w`/`y + h`. Title ID проверяется как ровно 16 hex-символов до использования в пути к иконке и до запуска. История запускает только сохранённые игры с корректным Title ID и NRO из разрешённого дерева. Проверки добавлены в host-тесты.

### 8. Дополнительная защита установщика и кэша иконок

Проверка конечной папки не защищает от symlink в родительском каталоге `switch`, `atmosphere` или `backup`; проверки добавлены для компонентов путей установки/удаления и регрессии на фиктивной SD-карте. Кэш иконок ограничен по размеру файла, а JPEG dimensions проверяются до загрузки в SDL_image; после декодирования размер поверхности проверяется повторно.

## Остаточные риски и блокирующие пункты

### P0 — runtime на физической консоли и соответствие целевой прошивке не подтверждены

- `projects/sSystem` заменяет критичный qlaunch и зависит от точного соответствия Atmosphère, libnx, libstratosphere и прошивки консоли.
- Успешный полный CI build подтверждён run #128 на SHA `72b8bff`: собраны и упакованы NRO, library applet, hbloader и qlaunch backend. Это не проверка фактической загрузки этих компонентов на консоли.
- Нет физической проверки HOME, запуска/закрытия игр, запуска NRO, сна/пробуждения, извлечения SD, аварийного восстановления и поведения после перезапуска.
- Аварийная комбинация кнопок — дополнительная страховка, не гарантия восстановления при повреждении sysmodule, несовместимом NPDM или отказе загрузки SD.

**Условие допуска:** проверка build manifest и всех хешей, сверка NPDM/capabilities и refs с целевой прошивкой, затем контролируемый runtime-тест на отдельной восстанавливаемой консоли/SD с заранее проверенным возвратом исходного qlaunch.

### P1 — host-tested backend state machine не подключена к production

`projects/common/source/BackendMachine.cpp` по-прежнему остаётся отдельной pure-logic моделью и не управляет production qlaunch-переходами. Её `backend_machine_test` не доказывает корректность полного lifecycle sysmodule; эту модель следует либо интегрировать, либо оставить явно как справочную/экспериментальную и не считать production coverage. При этом наиболее опасная повторно используемая часть watchdog уже вынесена отдельно: `projects/common/include/desknx/MenuLiveness.hpp` напрямую используется `projects/sSystem/source/main.cpp`, а `tests/menu_liveness_test.cpp` компилирует и проверяет именно этот production-контроллер. Тесты покрывают duplicate MenuReady, heartbeat deadlines, Busy start/end, heartbeat во время Busy, expiry boundary, cooldown и saturating arithmetic. Остающиеся production-переходы (HOME slot, applet lifecycle, title/homebrew start/exit, sleep/wake и recovery) всё ещё реализованы в sysmodule и требуют интеграционных/аппаратных сценариев.

### P1 — production IPC parser не покрыт host parser tests

`tests/protocol_parser_test.cpp` проверяет `source/ProtocolParser.cpp`, а реальные applet storages по-прежнему декодируются в `projects/sSystem/source/main.cpp::ParseMenuCommand`. Для устранения дублирования общий контракт версии/размера payload вынесен в `ProtocolRules.hpp`; теперь его вызывают и host parser, и production sysmodule, а `protocol_rules_test` проверяет legacy/current payload, запрещённые команды v1 и граничные размеры. Семантические действия (UID, допустимый путь NRO, Busy watchdog и переходы состояния) всё ещё требуют отдельных тестов/интеграции.

### P1 — ECS lifecycle требует runtime-верификации

В `ExternalContent.cpp` уже устранён прежний безусловный abort при создании ECS manager thread: поток подготавливается до публикации mapping, не запущенный поток уничтожается при rollback, а неожиданный возврат `LoopProcess()` фиксируется атомарным флагом. Перед следующей регистрацией завершившийся поток join/destroy и создаётся заново. Полная system-сборка #128 проходит. Остаточный риск — порядок kernel/service lifecycle и поведение при закрытии последней ECS session/повторной регистрации нельзя считать подтверждёнными только CI; нужны runtime-тесты на целевой Atmosphère.

### P1 — привилегии системных NPDM

NPDM меню и системного backend запрашивают широкие разрешения на файловую систему/сервисы. Для qlaunch-подобного компонента это может быть частично необходимо, но набор прав не был подтверждён по минимально необходимому списку на целевой Atmosphère. Перед выпуском требуется сверка capabilities и owner IDs с конкретной версией Atmosphère; не сужать их вслепую, но и не считать wildcard безопасным по умолчанию.

### P2 — надёжность файловых замен

Исправлено на уровне кода: общий `SafeReplace.hpp` применяется к layout, истории запусков, кэшу каталога/иконок и одноразовому запросу hbloader. Новый файл сначала записывается во временный путь, существующий destination перемещается в backup, а при ошибке публикации восстанавливается. Для layout backup сохраняется и при успешной записи; при отсутствии основного layout на старте проверяется резервная копия. Если восстановить/сохранить исходный файл безопасно нельзя, запись layout блокируется. Host-тесты покрывают успешную замену, отсутствие исходного файла, отказ публикации, rollback и сохранение backup. Остаются физические тесты SD/FAT и внезапного отключения питания.

### P1 — защита путей установщика

Установщик/удаление отказываются работать с `/`; установщик проверяет тип конечных объектов, а оба скрипта теперь также отклоняют symlink в родительских компонентах `switch`, `atmosphere`, `bin` и `backup`. Удаление дополнительно проверяет цепочки до manifest, qlaunch, NRO и recorded backup paths. Регрессионные тесты покрывают корень хоста, файл на месте qlaunch-каталога и symlink ancestors. Это не заменяет физический тест аварийного отката.

### P2 — оставшиеся сценарии установки/отката

Добавлены failure-injection сценарии с одноразовым отказом `mv` в критических точках публикации qlaunch при установке и восстановления предыдущего qlaunch при удалении. Проверяются восстановленные бинарники/NPDM и сопутствующие файлы, install marker/manifest, очистка stage/rollback каталогов и сохранение оригинального backup. Это существенно усиливает rollback-тесты, но не покрывает каждый `copy`/`rename`, внезапное извлечение SD, повреждённый manifest, потерю питания и все варианты повторного запуска после частичного сбоя. Перед реальным использованием полезен отдельный dry-run режим установщика.

### P1 — лицензионные тексты в собранном системном пакете

Исходное дерево хранит лицензию nx-hbloader (ISC) и уведомление/текст GPLv3 для sLaunch, однако системные упаковщики ранее копировали только `README.md` и `THIRD_PARTY.md`, не включая сами файлы лицензий в готовый архив. Упаковка исправлена: обе лицензии теперь включаются в system bundle. `THIRD_PARTY.md` указывает также на upstream uLaunch с GPLv2; правовую совместимость цепочки заимствований и требования к распространению комбинированного бинарного пакета всё ещё следует проверить до публичного релиза.

### P2 — воспроизводимость CI

В этой доработке system workflow будет добавлять в каждый новый архив `BUILD-MANIFEST.txt` (source commit, workflow run/ref, requested и resolved commits libnx/Atmosphère, версии host/cross-компиляторов и инструментов), отдельный `SHA256SUMS` для всех файлов пакета, включая build manifest (кроме самого списка), и внешний `.zip.sha256` для архива. Ограничение остаётся: контейнер `devkitpro/devkita64:latest` по-прежнему задаётся изменяемым тегом, его image digest не фиксируется; поэтому build manifest делает сборку проверяемее, но не полностью воспроизводимой. Следующий шаг — pin container digest и пакетные версии.

### P2 — охват тестами каталога и конфигурации

- Нет host-тестов парсера кэша каталога и истории.
- Нужны fuzz/property-тесты для повреждённых layout TSV, UTF-8, неизвестных типов, граничных размеров и столкновений плиток.
- Сборка standalone не компилирует hbloader и system backend; успешный обычный workflow нельзя считать проверкой всех компонентов.
- Следует отдельно проверить UI на реальной Switch: память/время сканирования каталога, большие коллекции, отключение SD и ошибки загрузки иконок.

## Границы аудита

Это статический аудит текущего кода и конфигурации плюс анализ доступных CI-результатов. Он не включает запуск на физической Nintendo Switch, проверку всех сочетаний прошивок/Atmosphère, fuzzing собранных бинарников или формальную проверку всех NPDM capabilities. Отсутствие найденного дефекта не является доказательством безопасности системной замены HOME.

### Высокий приоритет — LaunchSystemApplet намеренно отключён

Старый system run #96 показал compile error: `appletLaunchInteractiveSystemApplet` не объявлен в выбранной версии libnx. Вызов удалён; production backend валидирует allowlist, но пока явно отклоняет LaunchSystemApplet, потому что Web/Shop/PhotoViewer требуют разных input storage и lifecycle. Нельзя показывать пользователю успешный запуск, пока конкретный handler не реализован и не проверен.

Исправлена allowlist в `ProtocolRules.hpp`: ранее она ошибочно трактовала `0x0A..0x0D` как Web/Shop/PhotoViewer/Set. В libnx `0x0A` — Auth, `0x0B` — Cabinet, `0x0C` — Controller, `0x0D` — DataErase; актуальные ID перечислены правильно и закреплены host static_assert-тестами. Запуск библиотечных апплетов остаётся отключённым, а не притворяется рабочим.

### Высокий приоритет — сохранение файлов при сбое замены

Вынесена общая транзакционная замена небольших файлов в `SafeReplace.hpp`. Перед публикацией новый файл целиком пишется во временный; существующая версия переносится в резервную копию, а при ошибке публикации восстанавливается. Если само восстановление не удалось, резервная копия остаётся на диске для ручного восстановления. Применено к layout, истории запусков, кэшу каталога/иконок и одноразовому запросу hbloader. Добавлены host-тесты успешной замены, первого сохранения без существующего файла, отказа публикации, восстановления при отсутствующем destination и режима с сохранением backup.

Это защищает от потери прежнего файла при ошибке rename, но не заменяет физические тесты SD/FAT и проверку поведения при внезапном отключении питания.

### Средний приоритет — ограничение интенсивности IPC-логов

Добавлен production rate limit для `Command::Log`: не более 10 строк меню в секунду, а подавленные строки агрегируются в сводное сообщение не чаще одного раза в секунду. До этого имелся объявленный, но неиспользуемый счётчик для лимита логов, а валидные строки сразу записывались на SD. Это уменьшает риск избыточной записи на карту при ошибке UI/IPC.

### Уточнение восстановления layout

Замена layout теперь использует общий безопасный механизм, сохраняя `layout.bak` после успешной записи. При запуске резервная копия проверяется и при необходимости восстанавливается даже если основной `layout.tsv` отсутствует, а не только если он существует, но повреждён. Если исходный layout нельзя безопасно сохранить перед восстановлением, автоматическое сохранение блокируется, чтобы не уничтожить единственную копию.

### P1 — ECS server thread lifecycle

В ECS server перестал использовать безусловный `R_ABORT_UNLESS(CreateThread)`: поток подготавливается до регистрации loader mapping, а ошибка создания возвращается как обычный результат, пока внешняя регистрация ещё не изменилась. Если подготовка последующего шага регистрации не удалась, созданный, но не запущенный ThreadType уничтожается. Возврат `LoopProcess()` передаётся через atomic-флаг; при следующей регистрации завершённый поток дожидается, уничтожается и создаётся заново. Повторная регистрация уже известного пути тоже проверяет, что серверный поток жив и при необходимости перезапускает его.

Остаются проверки на реальной консоли: поведение после отключения последнего ECS session, перезапуск после неожиданного выхода LoopProcess и отказ CreateThread. CI может проверить компиляцию, но не полностью воспроизвести эти kernel/service lifecycle сценарии.

### P1 — тестируемая production-логика heartbeat/Busy

Heartbeat/Busy-правила вынесены в общий `MenuLiveness.hpp`, который напрямую используется `projects/sSystem/source/main.cpp` и компилируется без зависимостей от Switch SDK. Добавлены host-тесты: renew deadline, Busy pause, heartbeat во время паузы, окончание паузы с heartbeat и без него, ранний BusyEnd, запрет повторного Busy без нового heartbeat, cooldown, истёкший deadline, некорректные длительности и saturating tick arithmetic. Это устраняет дублирование именно для liveness-логики, но не подменяет полную state machine qlaunch и её аппаратные проверки.

### Failure-injection для installer/uninstaller

В `tests/test-recovery.sh` добавлены два сценария с одноразовым отказом `mv` в критической точке транзакции: публикация нового qlaunch при установке и восстановление предыдущего qlaunch при удалении. Проверяются восстановленные executable/NPDM для qlaunch, Menu, hbloader и NRO, ownership marker, install manifest, удаление временных stage/rollback каталогов и сохранность оригинальной резервной копии. Обёртка отказывает только один раз, чтобы аварийный trap мог выполнить реальные операции rollback. Эти тесты добавлены в обе CI-цепочки.


### Каталог приложений — исправление пагинации NS (2026-10-30)

В `nsListApplicationRecord` параметр `out_entrycount` является in/out: до вызова он должен содержать вместимость выходного массива, после вызова — фактическое число записей. Ранее `ReadGameRecords` передавал ноль, поэтому NS мог вернуть пустую страницу и список установленных игр оставался пустым. Исправлено: каждая страница запрашивает до 128 записей, offset увеличивается на фактический результат; добавлены host-тесты контракта пагинации.

Кэш каталога теперь не используется, если NS недоступен или вернул ошибку/некорректное количество записей. В результате ошибка системной службы не маскируется старым или пустым кэшем. В ScanResult передаются статус NS, код ошибки и отдельные количества игр и NRO; библиотека показывает диагностический код и счётчики.

В окне библиотеки добавлены сенсорные действия, двойное касание для добавления выбранного приложения, вертикальная прокрутка, сенсорные кнопки поиска/сортировки/фильтра/очистки и повторное сканирование. Повторное сканирование запускается отдельным SDL-потоком только после завершения предыдущего сканирования.


Сканирование Homebrew больше не пропускает целиком `sdmc:/switch/DeskNX/`: из каталога исключается сам файл `DeskNX.nro`, но пользовательские NRO внутри подпапок DeskNX теперь обнаруживаются. Это важно для тех, кто хранит свои программы рядом с данными лаунчера.
