Дата: 2026-10-30

Проверенный HEAD после диагностических изменений: `264e8505e67f9eae9203c0e2f452df35d00c0661`

## Резюме

Проект пока нельзя считать проверенным на реальной консоли. Предыдущая сборка действительно проходила CI, но это не подтверждало корректность работы NS на Switch. Повторная проверка обнаружила, что предыдущая правка инициализации NS была неполной: Transwitch не устанавливал актуальную версию Horizon OS до инициализации version-gated системных служб, в отличие от SLauncher.

В текущем HEAD исправлены три воспроизводимых по исходному коду дефекта:

1. Инициализация версии прошивки до NS/account и единый срок жизни системных сессий.
2. Повторное чтение и проверка JPEG с SD для каждой иконки на каждом кадре.
3. Перекрытие нижнего Dock подсказками управления и строкой статуса.

Обычная сборка GitHub Actions для HEAD завершилась успешно: run [41039111139](https://github.com/moroskinbiba-crypto/Transwitch/actions/runs/41039111139). Host-тесты и компиляция NRO/HOME applet прошли. Это не заменяет тестирование на консоли.

## Исправлено в текущем цикле

### P0 — порядок инициализации системных служб

**До исправления:** scanner открывал account/ns непосредственно из фонового потока. При этом фактическая версия HOS не запрашивалась и не передавалась в libnx до открытия NS. SLauncher выполняет `setsysGetFirmwareVersion` и `hosversionSet` в startup sequence до `accountInitialize` и `nsInitialize`.

**Исправление:** Transwitch теперь получает версию прошивки через setsys, вызывает `hosversionSet(MAKEHOSVERSION(...) | BIT(31))), затем открывает account/ns на основном потоке. Сессии остаются открытыми на всё время работы меню и закрываются после остановки сканера. Повторное сканирование использует ту же сессию, а не создаёт и закрывает её заново.

**Файлы:** `source/main.cpp`, `source/catalog.cpp`, `source/catalog.hpp`.

### P1 — лишние операции SD при каждой отрисовке

**До исправления:** `IconCache::get` выполнял `stat` и повторный разбор JPEG-заголовка до проверки resident texture cache. То есть уже загруженные иконки продолжали вызывать синхронные операции с картой памяти на каждом кадре.

**Исправление:** сначала выполняется поиск текстуры в памяти; файловые проверки и загрузка выполняются только при cache miss.

**Файл:** `source/IconCache.hpp`.

### P1 — пересечение элементов нижней панели

**До исправления:** Dock занимал область y=628..720, а подсказки кнопок и статус рисовались на y=650/670/699 поверх Dock.

**Исправление:** подсказки и статус перенесены в свободную полосу между рабочей областью плиток и Dock.

**Файл:** `source/main.cpp`.

### P1 — журнал диагностики на самой консоли

Добавлен ограниченный журнал `sdmc:/switch/DeskNX/catalogue.log` (текущий файл ротируется при размере более 128 KiB). Он фиксирует:
- версию прошивки и результат setsys/NS startup;
- Result-коды account и NS;
- начало и завершение `nsListApplicationRecord`, число полученных записей;
- результат запроса ApplicationView;
- запуск/завершение PDM statistics и число успешных ответов;
- итоговое количество игр/NRO, cache-hit, ошибки и длительность прохода.

Если после этой сборки игры не появятся, этот файл позволит отличить запрет доступа к NS от ошибки перечисления, чтения control data или зависания внутри конкретного системного запроса. Если журнал обрывается на `ns_list begin`, это укажет на зависание внутри NS enumeration.

## Оставшиеся риски и ограничения

### P0 — подтверждение обнаружения игр на консоли

Нужен реальный тест NS enumeration на Switch с записью:
- результата `setsysGetFirmwareVersion`;
- результата `accountInitialize` и `nsInitialize`;
- Result от `nsListApplicationRecord`;
- количества записей на каждой странице и общего количества Title ID;
- Result от `nsGetApplicationControlData` для нескольких приложений.

Пока этих значений с консоли нет, нельзя утверждать, что проблема обнаружения окончательно решена. Если NS вернёт ошибку доступа, нужно переносить перечисление в привилегированный SSystem/LibraryApplet контекст, а не продолжать менять UI-сканер.

### P1 — разные типы артефактов сборки

Обычный workflow `build.yml` публикует `DeskNX-sdcard` как пакет с standalone `switch/DeskNX/DeskNX.nro` и README. Это не полный системный пакет с qlaunch override и daemon. `DeskNX-menu-applet` — отдельные NSO/NPDM файлы, не готовый к самостоятельной установке пакет.

Полный системный bundle собирается отдельным экспериментальным workflow. Его нельзя устанавливать как повседневную замену HOME без проверки на тестовой консоли и готового сценария восстановления.

### P1 — нагрузка при первом сканировании

При первом заполнении кэша выполняются последовательные NS control-data запросы для игр, а затем PDM play-statistics запрос для каждой игры. Для большой библиотеки это может давать долгую начальную загрузку. Статистику следует сделать ленивой — запрашивать при открытии карточки игры или отдельным ограниченным фоновым проходом.

### P1 — устойчивость к повреждённому кэшу и внешним изменениям

Проверка наличия иконки игры сейчас в основном опирается на размер файла. Повреждённый JPEG может остаться в кэше и блокировать повторное получение иконки. Нужна проверка изображения при cache miss и безопасное удаление/перезапись некорректного файла.

### P1 — UI и геометрия

Интерфейс по-прежнему реализован большим монолитным `source/main.cpp` с большим количеством абсолютных координат для логического разрешения 1280×720. Перекрытие Dock исправлено, но это не полноценная адаптивная система компоновки. Нужны отдельные компоненты экрана, единые layout metrics, безопасные области и тесты hitbox для touch/D-pad.

### P1 — зависания и диагностика

Исправление повторных SD-операций убирает найденный источник постоянной нагрузки. Добавленный журнал локализует следующий зависающий этап, но само зависание на консоли ещё не проверено. В проекте пока недостаточно runtime-трассировки для различения:
- зависания NS IPC;
- долгого чтения SD;
- блокировки рендера/SDL;
- зависания system backend IPC.

Следующий инженерный шаг — лёгкий кольцевой лог с временными метками и этапами сканирования, запись в файл только при смене этапа/ошибке, плюс watchdog для фонового сканера. Нельзя безусловно прерывать системный IPC по таймауту, если API не гарантирует безопасную отмену.

## Недостатки автоматических тестов

Текущий CI хорошо проверяет host-модель раскладки, parser/protocol, backend state machine и скрипты восстановления. Но он не проверяет:
- реальный NS service lifecycle и разрешения;
- перечисление Title ID через libnx;
- NACP/icon extraction на настоящих control-data блоках;
- многократный redraw с реальными SDL textures;
- стабильность в течение длительного времени на консоли;
- фактическую touch/D-pad геометрию.

Успешная компиляция не является доказательством этих сценариев.
