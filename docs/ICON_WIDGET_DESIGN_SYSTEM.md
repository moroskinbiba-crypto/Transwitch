# Дизайн-система иконок и виджетов Transwitch

Статус: план следующего UI-этапа. Документ описывает целевую систему, а не утверждает, что все компоненты уже реализованы.

## 1. Принципы

1. **Обложка приложения и системная иконка — разные сущности.** Обложка игры остаётся полноразмерным изображением на плитке. Иконки действий, статусов, категорий и виджетов — компактная векторная графика. Не помещать произвольные SVG-глифы поверх игровых обложек без явной причины.
2. **Один визуальный язык.** У всех собственных иконок одинаковая геометрия, толщина штриха, окончания линий, радиусы и оптическое выравнивание. Не смешивать line icons, эмодзи, пиксельные символы и разноцветные системные глифы в одной панели.
3. **Семантика раньше декора.** Цвет и форма объясняют действие или состояние: фокус, включено, предупреждение, ошибка, недоступность. Акцент не должен заменять подпись там, где значение неочевидно.
4. **Виджет — мини-приложение, а не картинка.** Он получает единый контейнер, заголовок, состояние данных, контент и действие. Отрисовка не выполняет сетевые запросы, чтение SD или тяжёлые системные вызовы.

## 2. Система иконок

### 2.1. Базовая геометрия

- Исходный вектор: единый viewBox 0 0 24 24.
- Основной контур: 1,75–2 px; единая система round для linecap и linejoin.
- Минимальная толщина внутренней детали — 1,5 px; избегать линий и зазоров менее одного физического пикселя на целевом масштабе.
- Оптический центр проверять вручную: геометрический центр не всегда визуально совпадает с центром рисунка.
- Базовые экспортные размеры: 16, 20, 24, 32 и 48 px. Растрировать под фактический размер и масштаб экрана, а не масштабировать маленькую текстуру вверх.

### 2.2. Иерархия

| Класс | Назначение | Правило |
|---|---|---|
| App artwork | Игры и homebrew | Полноразмерная обложка/официальная иконка; не перерисовывать |
| System action | Settings, Power, Gallery, Controllers, Network | Единый контурный набор, 24/32 px |
| Widget identity | Clock, Storage, Battery, Nextendo, Quick Settings | Та же геометрия, но отдельные семантические глифы |
| State indicator | Online, Offline, Suspended, Update, Warning | Маленький бейдж или точка, в подробном экране всегда есть текст |
| Navigation | Back, Close, chevrons, Add, Move, Resize | Простые узнаваемые глифы |

### 2.3. Цветовые токены

Иконка не должна хранить жёстко заданный цвет темы. Рендерер получает семантические цвета из общей темы:

- icon.primary — основной контрастный глиф;
- icon.secondary — вторичная подпись/неактивная деталь;
- icon.accent — фокус и выбранное действие;
- icon.success — подтверждённое активное состояние;
- icon.warning — предупреждение;
- icon.danger — разрушительное действие или ошибка;
- icon.disabled — недоступное действие.

SOCOMA и v0.1 используют одни токены, но дают им разные значения. Акцент пользователя меняет icon.accent, а не перекрашивает всю иконку целиком.

### 2.4. Состояния интерактивной иконки

Для каждой кнопки/иконки определить состояния: idle, focused, pressed, disabled, active, warning, error. Фокус должен быть заметен не только цветом: допустимы обводка, подложка или короткий акцентный rail. Нельзя менять контур или геометрию при смене состояния — только токены и фон.

### 2.5. SVG-каталог

Каталог группируется по назначению, а не по экрану:

- navigation/ — back, close, chevrons, add, search;
- system/ — settings, power, gallery, controller, user, storage;
- widgets/ — clock, battery, monitor, recent, calendar, Nextendo, favorites, library, quick-settings;
- network/ — airplane, wi-fi, ethernet, bluetooth, signal;
- status/ — online, offline, suspended, update, warning, error.

Имена файлов семантические и стабильные. Не использовать случайные номера вроде icon_17.svg как единственный идентификатор. К каждой иконке добавить preview/test fixture и проверку viewBox, прозрачности, допустимых path-команд и предельной сложности.

### 2.6. Fallback и производительность

Порядок для приложения: SteamGridDB artwork → пользовательская совместимая иконка/пак → системная иконка из NsApplicationControlData или NRO-ресурса → спокойный нейтральный fallback. Не возвращаться к набору разноцветных квадратов с буквами как к основному стилю.

- SVG растеризуется один раз на комбинацию asset + size + scale + style.
- Повторные кадры используют текстуру из bounded LRU-кэша.
- Переключение темы/акцента не должно без необходимости перечитывать и декодировать исходный SVG.
- Чтение SD, декодирование, ресайз и сетевые операции — вне render/input thread.
- Удаление и замена artwork инвалидируют только нужный ключ; не сбрасывают всю очередь.
- При нехватке памяти сначала освобождается дальний/невыбранный artwork; выбранный элемент получает приоритет.

## 3. Дизайн-система виджетов

### 3.1. Единая структура

Каждый виджет собирается из общих примитивов:

1. **Surface** — фон, радиус, граница и глубина из токенов темы.
2. **Header** — маленькая векторная иконка, название, необязательный статус.
3. **Primary value** — главный показатель, крупная типографика.
4. **Secondary content** — контекст, подпись, мини-список или график.
5. **Footer/status** — время обновления, источник, offline/stale/permission state.

Контейнер, заголовок, отступы и интерактивные состояния общие; содержимое специфично для типа виджета. Виджеты не должны быть коллекцией несвязанных карточек.

### 3.2. Семейства компоновки

Сетка поддерживает только проверенные размеры 1×1, 2×1, 3×1, 2×2, 3×2, 2×3. Формат 3×3 не добавлять без изменения и тестирования модели сетки.

- **Compact** — короткая подпись + одно значение/индикатор; для 1×1 и узких плиток.
- **Wide** — горизонтальная композиция с несколькими элементами; 2×1 / 3×1.
- **Standard** — заголовок + основное значение + вторичная область; 2×2.
- **Dashboard** — несколько метрик/список; 3×2.
- **Portrait** — вертикальный список или регуляторы; 2×3.

Один виджет должен выбирать адаптивный вариант по фактическому размеру плитки, а не иметь отдельную несогласованную отрисовку для каждого размера.

### 3.3. Состояния данных

У каждого виджета должны быть стандартизированные состояния:

- loading — скелетон или ясное сообщение ожидания;
- ready — актуальные данные;
- stale — последнее известное значение с возрастом данных;
- empty — данных пока нет и показано следующее действие;
- unavailable — системная служба/разрешение недоступны;
- offline — сеть недоступна;
- error — операция завершилась ошибкой, есть понятная повторная попытка.

Нулевое значение не равно unavailable. Не показывать 0 как замену неизвестному статусу.

### 3.4. Действия и управление

- Одно основное действие по A/тапу — открывает полный экран или диалог виджета.
- Вторичные действия доступны через явную панель или редактор.
- Фокус контроллера всегда виден; переходы по элементам следуют пространственной структуре карточки.
- Действия виджета не должны конфликтовать с перемещением/изменением плитки в Edit Mode.
- Для быстрых переключателей есть мгновенная визуальная обратная связь и последующее подтверждение от системной службы. При отказе не отображать ложное состояние ON/OFF.

### 3.5. Спецификация основных виджетов

| Виджет | Основной экран | Вторичные данные | Действие |
|---|---|---|---|
| Clock | Время крупно | Дата, день недели | Открыть расширенные часы |
| Battery | Уровень и заряд | Подключённые Joy-Con и заряд | Открыть системную информацию |
| System Monitor | CPU/GPU/температура, если доступны | Частоты, HOS, возраст данных | Открыть диагностику |
| Recent Games | 2–4 последних игры | Последний запуск, мини-обложки | Перейти в Recent |
| Storage | Свободное/занятое место | Полоса/категории использования | Открыть состояние SD |
| Calendar | Сегодня/месяц | День недели и события, если источник существует | Открыть календарный экран |
| Nextendo | Всего онлайн | Активные игры/последнее обновление | Открыть популярные игры |
| Favorites | Избранные обложки | Число сохранённых игр | Открыть список избранного |
| Game Library | Быстрый каталог | Фильтр/недавно добавленные | Открыть библиотеку |
| Quick Settings | 4 системных статуса | Сеть и яркость | Открыть панель переключателей |

### 3.6. Обновление и нагрузка

- Виджеты потребляют только подготовленные snapshots.
- Частоты опроса задаются на уровне источника, не на уровне drawWidget.
- Network/NS/SD/temperature/audio/brightness — независимые источники со своими интервалами, таймаутами и статусами.
- Изменение настройки создаёт одну команду, а не запускает повторный опрос на каждом кадре.
- При скрытом/неактивном рабочем столе опросы замедляются или приостанавливаются.
- Добавить лимиты на одновременные операции и объём текстур/preview.

## 4. План реализации

### Этап A — Foundations
- Утвердить токены тем, акцента, отступов, радиусов и размеров иконок.
- Инвентаризировать все системные и widget glyphs, удалить дубли.
- Создать семантический SVG manifest и тест валидации.
- Утвердить API IconId, IconState, IconVariant, WidgetSurface.

**Приёмка:** все системные действия используют семантические IDs; иконки выглядят согласованно в 20/24/32/48 px и в обеих темах.

### Этап B — Icon renderer
- Единый renderer для system/navigation/widget icons.
- Theme/accent tokens применяются при рендере, а не записаны в SVG.
- Кэш по icon + size + style + scale, bounded LRU, lazy rasterization.
- Добавить visual regression fixtures для светлой/тёмной темы и состояний фокуса.

**Приёмка:** изменение темы не вызывает полного повторного чтения SVG; фокус и disabled state различимы.

### Этап C — Widget primitives
- Общие WidgetSurface, WidgetHeader, WidgetPrimaryValue, WidgetStatus.
- Layout adapters для пяти семейств размеров.
- Стандартизированные loading/ready/stale/empty/unavailable/offline/error.
- У каждого типа — собственный список допустимых настроек, без фиктивных строк общего редактора.

**Приёмка:** все виджеты имеют одинаковую иерархию, масштабы текста и поведение фокуса.

### Этап D — Widget redesign
- Поочерёдно перевести Clock, Battery, System Monitor, Storage, Calendar, Recent, Nextendo, Favorites, Game Library и Quick Settings на общие примитивы.
- Для больших плиток показывать больше данных, а не просто увеличивать пустой фон.
- Уменьшить визуальные подписи там, где значение самоочевидно; сохранить подпись и доступность на всех интерактивных элементах.

**Приёмка:** в одной сетке не встречается несколько конкурирующих визуальных стилей карточек.

### Этап E — QA / performance
- Тесты геометрии всех шести допустимых размеров.
- Проверка фокуса контроллера, касаний, drag/resize, смены темы и возвращения из системных апплетов.
- Замеры frame time, числа созданий текстур, cache hit/miss, задержки обновления snapshots.
- Тесты нехватки памяти, недоступных сервисов, отсутствующей SD и офлайн-режима.

**Приёмка:** виджеты не блокируют ввод и кадр; данные не выдают ложных состояний; визуальные регрессии обнаруживаются автоматическими fixtures.
