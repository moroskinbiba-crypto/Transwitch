# Repository cleanup — what stays, what goes

Inventory of `main` at `7053bcc76`. Every entry below is backed by a measurement or a
reference check, not a guess. Nothing here is deleted automatically: `scripts/cleanup-repo.ps1`
performs the deletions, dry-run by default.

## Bucket A — safe to delete now

| Path | Size | Why it is dead weight |
|---|---|---|
| `desknx-release.zip` | 565 KB | Built artifact committed as source. It is regenerated by the build; `prepare-romfs.js` even skips `.zip` when packaging. Nothing references it. |
| `.vite/deps/_metadata.json`, `.vite/deps/package.json` | 169 B | Vite dependency-cache bookkeeping. Machine-local, never needed for a build, and `.vite/` is missing from `.gitignore`. |
| `metadata.json` | 679 B | Leftover of an AI app generator (`MAJOR_CAPABILITY_SERVER_SIDE_GEMINI_API` was in it). Grep across the repo: **zero** references from code, scripts, CI or docs. |
| `src/services/switchHardwareService.ts` | 12 KB | Dead code: **no module imports it** (`from '...switchHardwareService'` → 0 hits). It advertises an HTTP bridge to `127.0.0.1:8080` that no shipped binary runs, which is exactly the misleading surface the plan's §3 warns about. The future transport is specified in `docs/HOMENX_FRONTEND_PLAN.md` instead of code that never executes. |
| `bun.lock` | 40 KB | CI installs with `npm install`; `package-lock.json` is the lockfile that actually governs builds. Two lockfiles for one manager is a guaranteed drift. Keep Bun as a runner, not as a second lockfile owner. |
| `docs/STAGE_1_SMOKE_TEST.md`, `docs/SWITCH_HARDWARE_PORTING.md` | 16 KB | Not referenced by README, CI, code or any other doc. `SWITCH_HARDWARE_PORTING.md` describes the bridge that does not exist (same problem as `switchHardwareService.ts`). |

Total: ~634 KB and four sources of confusion.

## Bucket B — keep

| Path | Why |
|---|---|
| `source/`, `include/` | The real native launcher; `projects/DeskNXMenu` builds `source/`. |
| `src-switch/main.cpp` | The standalone NRO shell that hosts the WebKit UI. Small, and the only thing the shipped NRO does. |
| `src/` (except the dead service above) | The React home screen — the current product surface and the behavioural reference for the native port. |
| `tests/` | 12 suites; six of them native and now run in CI. |
| `projects/DeskNXMenu`, `projects/common` | HOME applet and the shared IPC/liveness logic that the native path needs. |
| `scripts/prepare-romfs.js`, `scripts/check-tile-contract.mjs`, installers | All referenced by CI or by the applet lifecycle. |
| `romfs/` | **Keep for now** — see bucket C. Deleting it breaks `build.yml`'s `make -j2`, which has no `node` step to regenerate it. |
| `docs/COMPAT.md`, `HOME_INTEGRATION.md`, `CUSTOMIZATION.md`, `DIAGNOSTICS.md` | Referenced from README, CI workflows or `Diagnostics.hpp`. |
| `docs/AUDIT_2026-10-29.md`, `AUDIT_2026-10-30.md` | Historical record linked from README. Superseded by `HOMENX_FRONTEND_PLAN.md`, but they document *why* the current state looks like it does. |
| `icon.png`, `Makefile`, `Makefile.switch`, `.env.example`, `.gitignore`, `LICENSE`, `THIRD_PARTY.md` | Needed by the build, the NRO metadata or the license obligations. |

## Bucket C — needs your decision

| Path | Size | The trade-off |
|---|---|---|
| `romfs/` — three of the four copied layouts | 2.6 MB | `prepare-romfs.js` writes the same bundle to **four** mount points (`romfs/`, `html-document/`, `html-document/app.htdocs/`, `html-document/.htdocs/`) because the correct mount path differs between Horizon OS versions. The C++ tries `app.htdocs/index.html` → `index.html` → `.htdocs/index.html`, so at least two of the four are certainly used and one may be the only thing that works on some firmware. Recommendation: delete `html-document/assets/` and `html-document/.htdocs/` **after one smoke test on the console**, then add `romfs/` to `.gitignore` once `build.yml` gains a `node scripts/prepare-romfs.js` step (the devkitPro container has no Node). |
| `projects/sSystem`, `projects/hbloader` | 24 tracked files | The experimental qlaunch replacement and NRO loader. Brick risk, never hardware-validated, and the plan retires `sSystem` once its watchdog/IPC-validation/recovery logic is ported into the HomeNX path. Deleting now loses that logic; keeping costs maintenance. Recommendation: keep until the port lands, then delete in the same PR. |
| `src/data/mockCatalog.ts` | 24 KB | Demo catalogue. It is the only reason the web UI shows anything without hardware, so it stays while the WebKit path exists; it becomes dead the moment the native frontend replaces it. |
| `docs/AUDIT_2026-*.md` | 53 KB | Keep as history, or move to `docs/history/` to keep the top level readable. |
| `.env.example` | 71 B | Only `PORT`/`HOST` for the Vite dev server. Harmless; delete if you never use `.env`. |

## Deliberately not touched

- `THIRD_PARTY.md`, `LICENSE`, `projects/sSystem/COPYING.sLaunch`, `projects/hbloader/LICENSE.md` — licence texts. Removing any of them breaks distribution obligations, not build size.
- `projects/common/` — `ProtocolRules.hpp`, `MenuLiveness.hpp`, `BackendMachine.cpp` are actively tested.
- Any `.nro`, `.npdm`, `SdOut/`, `dist/`, `build/` — already untracked today (0 tracked files each). Add them to `.gitignore` so it stays that way.

## How to apply

```powershell
# see what would happen, no changes
pwsh scripts/cleanup-repo.ps1

# delete bucket A only
pwsh scripts/cleanup-repo.ps1 -Apply -Group safe

# after the console smoke test, also drop the duplicated RomFS layouts
pwsh scripts/cleanup-repo.ps1 -Apply -Group romfs
```

The script stages deletions with `git rm -r --cached` + filesystem removal, then prints the
`git commit` line to run. It is idempotent: already-deleted paths are reported and skipped.
